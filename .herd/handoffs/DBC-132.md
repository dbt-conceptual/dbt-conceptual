## What Was Built

Implemented Slack Socket Mode integration for the Herd MCP server, enabling the Architect to activate and interact with Mini-Mao from a Slack channel (`#mao`). This implements the architecture defined in HDR-0016.

## Files Created

### Core Implementation

**`.herd/mcp/src/herd_mcp/session_manager.py`** (262 lines)
- Manages thread-to-session mapping for Claude CLI processes
- Each Slack thread = one Mini-Mao session
- Session lifecycle: spawn → active → idle timeout / explicit shutdown
- Uses `asyncio.create_subprocess_exec` to spawn `claude` CLI
- Captures `session_id` from streaming JSON output for `--resume` support
- Idle check loop runs every 30 seconds, closes sessions idle > timeout
- Shutdown command detection: "go to sleep", "stand down", "terminate now"
- Key methods:
  - `send_message()`: Route message to session (create if needed)
  - `close_session()`: Terminate process and cleanup
  - `close_all()`: Shutdown all sessions (daemon stop)

**`.herd/mcp/src/herd_mcp/slack_listener.py`** (192 lines)
- Slack Socket Mode client using `slack_sdk.socket_mode.aiohttp`
- Connects on startup using `SLACK_APP_TOKEN`
- Listens for `message` events in `#mao` channel
- Filters:
  - Only authorized users (from `HERD_AUTHORIZED_USERS` env var)
  - Ignores bot messages (including its own)
- Routes new messages → new session, thread replies → existing session
- Posts Mini-Mao's response back to Slack thread
- Error handling: posts errors to thread, logs exceptions

**`.herd/mcp/src/herd_mcp/daemon.py`** (108 lines)
- Combines REST API server + Slack listener in one asyncio event loop
- Validates required env vars (`HERD_SLACK_TOKEN`, `SLACK_APP_TOKEN`)
- Graceful shutdown: stops Slack listener → session manager → REST API
- Configuration via environment variables:
  - `HERD_API_HOST` / `HERD_API_PORT`: REST API bind address
  - `HERD_PROJECT_PATH`: dbt-conceptual project path
  - `HERD_IDLE_TIMEOUT`: Session idle timeout (default: 180s)
  - `HERD_SLACK_TOKEN` (xoxb-...): Bot token for API calls
  - `SLACK_APP_TOKEN` (xapp-...): App token for Socket Mode

## Architecture Decisions

### Claude Code CLI (not API)
Using the local `claude` CLI instead of the Anthropic API:
- Uses Architect's subscription (no separate API key needed)
- Runs locally with full tool access (file system, MCP tools)
- Session continuity via `--resume` flag

### Socket Mode (not webhooks)
Using Slack's Socket Mode instead of HTTP webhooks:
- No public endpoint needed
- Works behind NAT/firewall
- Slack pushes events via WebSocket

### Thread-scoped sessions
Each Slack thread is an independent session:
- Multiple threads can run concurrently
- Thread timestamp is the session key
- Session state is isolated

### Process-per-message model
Each message spawns a new `claude` CLI process:
- Initial message: no `--resume` flag
- Follow-up messages: `--resume <session_id>` to continue conversation
- Process exits after response (not kept running)
- This matches how the Claude CLI works (stateless invocations)

## Environment Variables

**Required**:
- `HERD_SLACK_TOKEN` (xoxb-...): Bot token for API calls
- `SLACK_APP_TOKEN` (xapp-...): App token for Socket Mode

**Optional**:
- `HERD_API_HOST`: REST API bind address (default: 0.0.0.0)
- `HERD_API_PORT`: REST API port (default: 8420)
- `HERD_PROJECT_PATH`: dbt-conceptual project path (default: cwd)
- `HERD_IDLE_TIMEOUT`: Session idle timeout in seconds (default: 180)
- `HERD_MAO_CHANNEL`: Channel name (default: "mao")
- `HERD_AUTHORIZED_USERS`: Comma-separated Slack user IDs (default: none = all allowed)

## How To Run

```bash
# Set required tokens
export HERD_SLACK_TOKEN="xoxb-..."
export SLACK_APP_TOKEN="xapp-..."

# Optional: restrict to specific users
export HERD_AUTHORIZED_USERS="U_ARCHITECT,U_ADMIN"

# Run daemon
cd /path/to/dbt-conceptual
python -m herd_mcp slack
```

## Usage

1. In Slack, open `#mao` channel
2. Send a message: "Hello Mini-Mao, what's the status?"
3. Mini-Mao responds in a thread
4. Follow-up messages in the same thread continue the conversation
5. Session auto-closes after 3 minutes of inactivity
6. Explicit shutdown: "go to sleep", "stand down", or "terminate now"

## Known Issues / Future Work

1. **Session recovery**: If daemon crashes, active sessions are lost. Could persist session state to DuckDB.

2. **Response streaming**: Currently waits for full Claude response before posting to Slack. Could stream responses in real-time (update Slack message as tokens arrive).

3. **Rate limiting**: No Slack API rate limit handling. Could add exponential backoff.

4. **Session metrics**: No tracking of session duration, message count, etc. Could log to DuckDB.

5. **Multi-channel support**: Currently hardcoded to `#mao`. Could support multiple channels.

6. **User context**: Could pass more Slack context to Claude (user timezone, profile, etc.).
