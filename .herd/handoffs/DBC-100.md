# Handoff: DBC-100 — Listener Integration + Platform Hardening

## What was done

### 1. Identity Resolution Module (`src/herd_mcp/identity.py`)
Created comprehensive identity resolution system:
- `get_agent_name_from_env()` - Reads HERD_AGENT_NAME environment variable
- `resolve_agent_code(agent_name)` - Maps agent name to agent_code in database
- `resolve_or_create_agent_instance(agent_code, ...)` - Gets or creates active agent instance
- `resolve_identity()` - Main entry point that returns complete identity dict

Key features:
- Auto-creates agent instances on first session start
- Returns existing active instance if one exists (doesn't create duplicates)
- Uses default model from agent_def if not specified
- Records lifecycle activity in agent_instance_lifecycle_activity table

### 2. Database Seed Script (`scripts/seed_db.py`)
Created idempotent migration script that populates:
- **agent_def table**: mini-mao, grunt, pikasso, wardenstein, shakesquill with their roles, email, branch prefix, default models
- **model_def table**: claude-opus-4-6, claude-sonnet-4-5, claude-sonnet-4, claude-haiku-4 with current pricing (as of 2026-02-09)

Features:
- Idempotent: Safe to run multiple times without creating duplicates
- Updates existing records with new values if schema changes
- Reads HERD_DB_PATH environment variable (defaults to `.herd/herd.duckdb`)
- Can be run standalone: `python3 scripts/seed_db.py`

### 3. MCP Configuration Template (`mcp-config.json`)
Created ready-to-use MCP server configuration for agent `.mcp.json` files:
- Stdio transport with `python3 -m herd_mcp`
- Environment variables: HERD_AGENT_NAME, HERD_DB_PATH
- Full description of server purpose

Agents can copy this into their `.mcp.json` and set their HERD_AGENT_NAME.

### 4. Integration Documentation (`README.md`)
Created comprehensive setup guide:
- Installation steps
- Database seeding instructions
- MCP configuration guide
- Available tools reference
- Identity resolution explanation
- Database schema overview
- Troubleshooting guide

## Open questions for Architect

1. **Craft and Personality Versioning**: Should we seed craft_version and personality_version tables now, or wait until those markdown files are more stable? Current implementation creates instances without craft/personality versions.

2. **Agent Email Addresses**: Using `<agent>@herd.local` for now. Should these be real email addresses or GitHub usernames for GitHub commit attribution?

3. **Model Pricing Updates**: How should we handle model pricing updates in the future? Re-run seed script? Separate migration? The current approach updates existing records.

4. **Agent Instance Lifecycle**: When should agent instances be ended (agent_instance_ended_at set)? On session end? Manual decommission? Never?

5. **Deleted Agents**: Should we support soft-deleting agents (setting deleted_at)? Current seed script only handles active agents.

6. **Identity in Tools**: Should all tool implementations in `tools/*.py` be updated to use the new identity.resolve_identity() function, or keep using the simple get_agent_identity() in server.py?
