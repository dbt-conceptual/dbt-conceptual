## Summary

Implemented a comprehensive historical backfill script to populate HerdDB with data from Linear and GitHub. The script fetches all tickets, projects, PRs, and commits, then upserts them into DuckDB using idempotent logic.

### Tables Populated

The script populates these DuckDB tables:

1. **`herd.project_def`** - Linear projects
2. **`herd.ticket_def`** - Linear tickets (all DBC-* tickets)
3. **`herd.pr_def`** - GitHub PRs (all merged PRs)
4. **`herd.agent_instance_pr_activity`** - PR commits
5. **`herd.agent_instance`** - Special `backfill-000` agent instance

## Implementation Notes

### Linear Integration

The script uses the existing `linear_client.py` module's `_graphql_request()` function directly for fetching tickets and projects. I implemented pagination using Linear's `pageInfo` (hasNextPage, endCursor) to handle large datasets.

### GitHub Integration

Used the `gh` CLI for fetching PRs and commits:
- `gh pr list --state merged --json ...` for PRs
- `gh pr view <number> --json commits` for commit history

### Ticket Code Extraction

The script tries multiple sources in order:
1. PR title (regex: `\bDBC-\d+\b`)
2. Branch name (regex: `\bDBC-\d+\b`, case-insensitive)
3. PR body (regex: `\bDBC-\d+\b`)

### Agent Code Extraction

Extracts agent from branch prefix pattern:
- `herd/grunt/dbc-120` → `grunt`
- `herd/pikasso/feature` → `pikasso`

### Idempotency

All upsert operations follow this pattern:
1. Check if record exists (SELECT by primary key)
2. If exists: UPDATE with new data
3. If not exists: INSERT new record

This makes the script safe to re-run without creating duplicates.
